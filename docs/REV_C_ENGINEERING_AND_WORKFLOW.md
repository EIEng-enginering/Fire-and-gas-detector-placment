# Rev C implementation and boundaries
16 November 2026. v0.3.0a1. DEVELOPMENT BUILD / UNVERIFIED.

This extends the preserved Rev B candidate. It is a functioning offline synthetic study workflow; it is not a complete or qualified Fire and Gas engineering product. Q1–Q10/F01–F10 remain proposed. No Git actions, client inputs, live AI/API calls, publication, binary release or engineering promotion occurred.

## Implemented changes
- Replaced the detector QTableWidget with the same cached virtual QTableView used for the other registers. All four registers filter cached fields, sort with native numeric values, copy selected cells, retain per-PC column layouts/visibility and support a follow-row display aid. Copied cells receive a visible highlight. Cut is explicitly refused for required fields; it is not falsely reported as implemented.
- Added detector creation and edit forms with evidence selection/new-source entry, type, SI XYZ, azimuth/elevation/roll and manufacturer/model/sensitivity placeholders. Missing response curves still prohibit engineering coverage. Explicit marker creation works in a new or existing synthetic scene.
- Added equipment and fire/gas zone forms. Equipment can reference a selected geometry component. Zones have explicit SI bounds and design-criterion references. Zone boxes and detector orientation arrows are display annotations, not coverage/FOV geometry.
- Added atomic workspace commands: new evidence+detector+marker, detector edits/removal with reference checks, equipment/zone creation/edit/removal, numeric/type multirow paste, and reviewed scene append/replace. Reversible entity changes and full prior values are retained in the immutable ledger. Generic undo/redo survives reopen, invalidates redo on a new command and refuses intervening conflicting edits. Retained source bytes/provenance and calculation history are intentionally not erased by undo. Legacy name/source APIs still have their separate history.
- Clipboard paste is previewed, requires a named editor and commits the whole set or none. IDs, evidence and review states cannot be pasted. Visible sorted/filtered row order is mapped to stable IDs; linked markers move within the same command.
- Added a geometry review window with source/frame/hash/diagnostics and explicit APPEND or REPLACE. Imports remain OBJ and ASCII STL only. Duplicate source components and changed source bytes are refused. A replacement that breaks equipment geometry links generates an OPEN blocking preparation finding.
- Added an evidence/findings inspector and deterministic preparation findings. Missing manufacturer-response implementation, missing orientation/marker, missing zone criteria, stale runs and orphan geometry links are shown separately. Findings do not constitute standards compliance assessment or human acceptance.
- Added cancellable report export from the Case menu using a frozen normalized snapshot and a subprocess. The snapshot carries the actual illustrative viewer PNG, hash and camera state. Excel/Word/PDF/JSON/ZIP use the same records/findings. Figure hashes are checked. Existing record_rows counts refer to primary records; finding_rows separately counts findings; QA all_export_rows includes both.
- Added a local supplied-synthetic-exercise runner. Method selection is closed; unsupported engineering methods remain refused. Every new run records software version, named method, input/scene hashes and source-module hashes. Old runs remain historical and do not gain invented source hashes.

## Case hardening
Rev C holds an OS advisory writer lock on a stable `<case>.writer.lock` sidecar while the case is open. This survives atomic replacement and prevents cooperating Rev C sessions using different runtime folders or symlink paths from writing together. Hard-linked case aliases are refused to prevent identity forking. The sidecar is operational, contains no project data, may persist after close, and is excluded from return packs. The portable study remains one .fgcase file.

After the OS lock is obtained, POSIX runtime lock metadata is quarantined only when its recorded PID is demonstrably absent. A live or uninspectable PID is refused, preserving compatibility with an older app that lacks the native fence. Windows stale-runtime-lock cleanup remains disabled pending verified process inspection and real-platform recovery tests; os.kill(pid,0) is deliberately not used on Windows. No PID-only decision overrides an active OS lock. Working-copy recovery remains an explicit choice. Save metadata now uses atomic/fsynced JSON and a pending-source/work hash journal. A crash/failure after case installation but before metadata finalization can be reconciled on explicit recovery. Source hashes are rechecked immediately before replacement.

Executed tests include separate runtime folders, symlink aliases, hard-link refusal, process kill, injected pre-replace failure and injected post-install metadata failure. These prove the specified Linux cases only. Uncooperative older versions/external writers, remote multi-host/OneDrive semantics and Windows OS lock behaviour still require qualification. The lock sidecar must be writable alongside the case.

## New numerical field model
`engine/concentration.py` accepts only closed `fg-synthetic-field/1` inputs with metres, seconds, ppm, explicit sorted axes, `[t,z,y,x]` flattened data, source hash/revision/locator and SYNTHETIC classification. Maximum 200,000 nodes is a development resource bound. Spatial trilinear and linear time interpolation refuse extrapolation. Beam integration uses an explicitly selected even Simpson subdivision count; no detector physics, CFD, obstacle interaction or gas-specific LEL conversion is inferred.

Verification uses an independently specified affine field, whose line integral equals chord length times endpoint mean, and a piecewise-linear field with exact integral 8.71 ppm*m from triangle+rectangle areas. The convergence example decreases absolute error from about 0.04333 at two subdivisions to about 0.0001042 at 128. This is one constructive benchmark, not a general error guarantee. A first-order step-response exercise requires an explicitly supplied tau and is labelled synthetic; no manufacturer response is invented. Nonfinite inputs and integral overflow are refused.

## Executed evidence and defects
See TEST_RESULTS/REV_C_FINAL_SUMMARY.json for final counts and fresh-extraction status, REV_C_WORKFLOW_RETEST/DELIVERY logs for actual Qt workflows, REV_C_10000_DETECTORS.json for measured Linux detector-grid results and REV_C_MUTATIONS.json for deliberately broken writer/undo implementations caught by tests.

Defects found and corrected without relaxing tests:
1. Pasted integer coordinates differed from SQLite REAL values in undo conflict comparison: command numeric fields are normalized before logging.
2. Imported source attachment was inserted before new evidence, violating its FK: source evidence, scene and attachment now commit together.
3. Undo attempted to erase evidence still referenced by retained raw source: import provenance now remains retained and separately audited; scene remains reversible.
4. A table-highlight patch incorrectly added cell-index code to headerData: corrected the implementation and added a child-process regression exercising all relevant header/cell roles, numeric sorting, copy and follow-row behaviour. Qt failure logs are retained.

## Remaining product work
The software is more usable but WP02–WP12 are not fully accepted. Main gaps: qualified detector response methods/data, standards clause access, robust STEP/binary STL/CAD diagnostics and self-intersections, full geometric/physical uncertainty validation, general explicit placement relationships and complete legacy-command history, arbitrary structured record import, production report templates, durable online AI consent/security, live external integrations, Windows acceptance and independent engineering review. No prototype numerical exercise can be used as a facility coverage result.
