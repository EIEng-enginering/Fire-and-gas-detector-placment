## Bulk register preparation
CSV is strict UTF-8; XLSX uses one literal-value sheet named Registers. Required unique headers are defined in services/bulk_import.py and supplied example templates.1..2000 rows,4MB raw and32MB expanded workbook limits apply. Each row explicitly declares SYNTHETIC, CREATE/UPDATE, DETECTOR/EQUIPMENT, stable ID and existing synthetic evidence. Detector XYZ/orientation are explicit SI metres/degrees; no zero orientation is invented. Detector-only/equipment-only fields cannot silently cross kinds. Duplicate IDs, unknown headers, formula/error cells, nonfinite numbers, missing evidence and mounted direct edits are refused. Equipment import currently supports description/type reference, XYZ and optional geometry link; zones are not imported.

A preview stages on an in-memory SQLite clone, applying the existing validators and computing complete before/after changes. It cannot mutate the live case. A killable worker receives a SQLite snapshot, never the live session connection. Commit requires actor/rationale, matches case UUID/state/ledger, rebuilds from retained exact source bytes and rejects tampered/stale plans. One workspace command applies all rows atomically, marks calculations stale and supports persisted undo/redo. Exact raw bytes/base64/hash and review summary remain in an append-only source ledger after undo; retained history does not imply current application. Commit reconstruction still runs on the owning UI thread; large/dense-case timing needs more tests. The2000-row benchmark is a development observation only.

## Facility revision reconciliation
fg-geometry-revision/1 is a closed synthetic JSON request containing a validated facility scene and explicit mount_decisions. Stable IDs identify added/removed/changed component geometry/frames. Detector display markers are retained in an explicit SI frame; user source must not supply replacement detector markers or the reserved frame ID. Exactly one action is required per affected mount: FOLLOW_COMPONENT with an explicit target component, reason/evidence, or KEEP_WORLD_DETACH with no target. There is no implicit detector move or inferred correspondence. Missing engineering-record component references block revision until explicitly resolved.

Following reuses existing source-frame anchor coordinates, physical metre offsets and local orientation, recomputes world pose and source fingerprint, then moves its marker atomically. It is frame-local positioning, not automatic projection onto a moved mesh surface or mechanical mounting qualification. Stale/missing original mounts and changed source anchor units refuse following; detach/redeclare manually. Full frame rotations/translation are handled by the existing tested mount engine. Geometry-only label/metadata/evidence/parent changes need richer reconciliation; component fingerprints currently focus on frame/mesh. All revision changes and mount decisions are previewed and retained, with undo/redo.
