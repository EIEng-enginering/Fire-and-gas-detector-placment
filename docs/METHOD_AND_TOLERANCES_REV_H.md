# Coverage method and tolerances — Rev H (FG-FLAME-GEO/1.1, FG-GAS-GEO/1.1)

Status: DEVELOPMENT software. Results are COMPUTED - UNREVIEWED until an engineer review record exists
(see "Result lifecycle"). Nothing here is independently verified, certified or released for safety use.

This document replaces the Rev G description in `docs/REV_G_COVERAGE_METHOD.md` wherever the two differ.
The finding IDs (F01–F25) refer to `INDEPENDENT_REVIEW_REV_G.md`.

## 1. Discretisation and the cell measure (F01, F14, F20)
* The zone AABB is cut into cells of the user grid spacing `h` (VOLUME), or into plan cells at the
  user slice elevations (SLICES). Boundary cells are clipped to the zone. Each stored sample row
  keeps the clipped cell bounds `cell_low`/`cell_high` (row format in `samples.row_format`).
* **Free measure of a cell** = cell measure − |cell ∩ (obstructing solids ∪ basis exclusions)|.
  * If only axis-aligned box solids touch the cell, the measure is **exact**. It is the union of the
    clipped boxes, computed by coordinate compression, so overlapping solids are never double counted.
    The exclusion part is |cell ∩ E|. The obstruction part is |cell ∩ (S ∪ E)| − |cell ∩ E|, so an
    exclusion overlapping a solid is counted once.
  * If any other closed mesh touches the cell, the measure uses **adaptive bisection**. A sub-cell is
    refined when an exact separating-axis test (triangle vs box; triangle vs plane rectangle in
    SLICES) shows a solid boundary passing through it. The default depth is 4 levels (2^d children per
    level). Untouched sub-cells are wholly inside or outside a closed solid, so classifying them by
    their centre is exact. Leaf sub-cells that are still touched are classified by their centre,
    and their whole measure is added to a **rigorous bound** (`measure_error_bound`, reported per
    zone and raised as a finding).
  * Box test boundary rule: a point is inside only when it is more than `tolerance_m` inside every face.
    Points on a face are free.
* **Detection sampling.** Detection is evaluated at ONE representative free point per cell. This is the
  centre when it is free; otherwise it is the free sub-sample point nearest the centre (4^d, 8^d, then
  16^d search). The coverage fractions are therefore **sampled-cell fractions**: the eligible free
  measure of the cells whose representative point is detected, divided by the total eligible free
  measure. They are not exact geometric volume fractions of the detected region. If no free point is
  found, the cell's free measure is reported as `unsampled_free_measure` (a finding) and is excluded
  from the eligible measure.

## 1a. Extended fire target (F14)
* For a non-point fire target, `min_visible_fraction` is a **sampled-point visible fraction**: the
  equal-weight fraction of the target's centre/perimeter sample points at the configured heights that
  are in line of sight and inside the field of view. It is not a projected flame area, a view factor or
  a validated radiometric response, and it is not grid-checked separately. Reports print it as
  "min sampled-point visible fraction". A justified visibility/response model is OPEN work; until then the
  value must not be used as an area or performance claim.

## 2. Solid membership (F02, F03)
* Axis-aligned 8-vertex boxes use the exact box test above.
* Every other mesh must be topologically **closed**: no boundary edges, no non-manifold edges, no
  duplicate faces and consistent winding. Membership then uses the **generalised winding number**
  w(p) = Σ Ω_t(p) / 4π. Ω_t is the signed solid angle of each triangle (Van Oosterom & Strackee, 1983).
  The point is inside when |w| > 0.5 and it is more than `tolerance_m` from every triangle, using an
  exact point–triangle distance. The result does not depend on triangle order or triangulation, and
  shared edges cannot be double counted.
* Open or non-manifold meshes enclose **no volume**. They still obstruct line of sight as surfaces,
  and a finding is raised. A basis-excluded component with an open mesh is a BLOCKING finding.
* Basis exclusions use the real mesh membership, not the AABB.

## 3. Orientation (F04, F19)
* The detector frame is the column set of `domain.mounting.rotation(az, el, roll)`. This is the same
  matrix used for mounts, the viewer overlay and the layout options:
  * local X is the boresight (cos az·cos el, sin az·cos el, sin el);
  * local Y is left;
  * local Z is up;
  * roll is a right-handed rotation about the boresight.
* For a target at offset d: x = d·X, h = atan2(|d·Y|, x), v = atan2(|d·Z|, x). The target is accepted
  when x > 0, h ≤ FOV_H/2 and v ≤ FOV_V/2 (a rectangular FOV), and the distance is within
  contour_range(off-axis) × scale. The contour gives 0 beyond the last table angle; there is no
  clamping.
* The viewer FOV overlay is generated by `engine.coverage.fov_outline`. It applies the same predicate
  around the rectangle perimeter, so the overlay never shows response outside the engine's support.

## 4. Line of sight and the mount standoff (F05, F06)
* Sight lines always start at the detector position and end at the target point.
* `standoff_m` only ignores hits on the detector's own declared mount component (`detector_mount`
  record), and only within the standoff radius. Any other geometry between the detector and the
  target blocks. A wall can no longer be skipped.
* Open path: the TX ignores only its own mount component near the TX end. The RX ignores only its
  receiver record's `mount_component_id` near the RX end. A beam not longer than 2 × standoff is
  inoperative (BLOCKING finding).
* Tolerance `tolerance_m` (eps):
  * the segment/triangle test treats hits within eps as hits;
  * a segment coplanar with a triangle within eps is **indeterminate**. It is counted in
    `indeterminate_rays` and treated as blocked (conservative);
  * the scene broadphase AABBs are inflated by eps, so the scene result equals the per-mesh result
    for near-edge rays.

## 5. Gas (unchanged physics, F05/F18 guards)
* The design cloud is a sphere or an axis-aligned ellipsoid centred at each representative point.
* Point detectors respond inside the cloud (inclusive, 1e-12 relative tolerance) when the cloud
  concentration is at or above the alarm threshold.
* Open path responds when the exact chord length × %LEL/100 is at or above the LEL·m threshold
  (1e-12 tolerance).

## 6. Voting
* 0ooN is the fraction with exactly 0 votes. kooN is the fraction with at least k votes. So 0ooN + 1ooN = 1,
  and the kooN fractions are monotonically non-increasing.

## 7. Two-grid check (F07)
* With refinement r > 1, the zone is recomputed at h/r. The status is one of:
  * `GRID AGREEMENT (not an error bound)`: every |Δfraction| ≤ tol and |Δeligible|/eligible ≤ tol;
  * `GRID DISAGREEMENT - refine grid`;
  * `UNRESOLVED FEATURE - refine grid`: a detector reach (contour max × scale) < 2h, or the minimum
    design-cloud diameter < 2h;
  * `NOT EVALUABLE - no eligible measure`: the eligible measure is zero or a fraction is undefined;
  * `NOT CHECKED (refinement 1)`.
* The word "converged" is not used. No Richardson extrapolation is done, because no asymptotic order
  exists for this discontinuous indicator. Agreement between two grids is not an error bound.
* Worked example (regression test): a ±45° sector of radius 0.28 m at slice z=0 in a 1 m × 1 m zone.
  The exact area is π·0.28²/4 = 0.061575 m². Rev G's 1.0/0.5 m grids gave 0 and "CONVERGED". Rev H
  reports UNRESOLVED FEATURE. A 0.05 m grid gives 0.0616 ± 0.006.

## 8. Sensitivity (F24)
* The ±10 % contour-range sensitivity (factors 0.9, 1.1) is fixed when the run envelope is prepared.
  It is part of the input envelope (`sensitivity.enabled`, `sensitivity.range_factors`) and its hash.

## 9. Method identity and currency (F08)
* `implementation_files` is the full transitive closure of fgmapping imports from the method entry
  modules (static AST scan, including function-level imports):
  * ZONE_COVERAGE: engine/coverage.py, engine/detection.py, services/coverage.py;
  * SCENARIO_COVERAGE / LAYOUT_OPTIONS: also engine/scenario_coverage.py, engine/scenarios.py,
    engine/optimisation.py and services/scenario_coverage.py.
* Hashes are of LF-normalised file bytes, keyed by paths relative to src/fgmapping. They do not depend
  on machine paths or line endings. They hash only source files, never results, so they are not
  circular.
* Policy: a change to ANY file in a method's closure makes that method's stored runs STALE. Files
  outside the closure (UI, reports, heatmaps) do not.

## 10. Result lifecycle (F12)
* Every new run is `COMPUTED - UNREVIEWED`.
* `ENGINEER REVIEWED` requires a ledger record (`REVIEW_COVERAGE_RUN`) with reviewer, UTC time,
  disposition, the run input hash and the result SHA-256.
* `INDEPENDENTLY VERIFIED` requires a further `VERIFY_COVERAGE_RUN` record by a different person,
  with registered evidence.
* Any change to the inputs (STALE) or to the result gives `REVIEW INVALIDATED`. Records are immutable.
* The software never creates review records by itself.
