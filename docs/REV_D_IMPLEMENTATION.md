# Rev D implementation and engineering limits
All new methods and data are DEVELOPMENT / UNVERIFIED; synthetic development only.

## 1. Component mounting and orientation
An explicit detector_mount row links a detector to a facility component and source fingerprint. Source-local anchors transform through the component frame with declared unit scaling. Physical metre offsets rotate through normalized frame axes without being scaled again. Local Euler orientation composes with the source frame; azimuth is +X toward +Y, elevation above XY, roll about local +X. Gimbal reconstruction is deterministic; equivalent Euler triples need not be identical. Independent known answers check rotations, mm scaling and pose reconstruction. Parent changes mark mounts STALE_SOURCE/MISSING_COMPONENT; they do not silently reposition or approve a detector. Remount explicitly. Direct edit/paste of mounted detector coordinates is refused; detach retains last world position. Marker cubes/orientation arrows remain illustrative.

## 2. Finite-target geometric inspection
An explicit rectangle center, orthonormal U/V, positive width/height and grid define equal-area midpoint samples (1..4096). Selected facility meshes obstruct segment rays; detector display markers are excluded. Each sample retains point, area, CLEAR/BLOCKED/INDETERMINATE and hit trace. Coplanar cases and closed-mesh AABB endpoint ambiguity remain indeterminate. No point-in-solid, self-intersection, detector radiation/FOV, response, attenuation, gas dispersion or physical coverage claim exists. Unknown area remains in total denominator: lower=clear/total, upper=(clear+indeterminate)/total, single fraction absent if indeterminate. Tolerance must be finite positive; zero/sub-tolerance rays remain unknown. Half-area constructive oracle returns0.5 at16/64/256/1024 samples; area conservation and transformed mounting have independent checks. Aligned examples do not establish convergence for arbitrary industrial geometry. Worker is killable/time-bounded; POSIX memory/CPU bounds do not implement Windows Job Objects. Saved runs retain inputs, complete results, version, scene and implementation hashes; stale source refused.

## 3. Basis and readiness
fg-study-basis/1 records an explicit revision, single study type, coordinates, target, fuel/gas, positive voting requirement, criterion reference, supplied target fraction or NOT SUPPLIED, exclusion reasons/evidence and uncertainty reference. There is no approved target default. INPUTS_PRESENT only means preparation fields/links are present; engineering_calculation_status always BLOCKED. Stale mounts, corrupt raw datasets, mismatched vendor identity/sensitivity, missing evidence, impossible voting, unsupported method scope and anomalous stored status produce blockers. BOTH requires separately defined method bases. An exclusion is a documented preparation choice; it does not authorise removing denominator area from a qualified engineering calculation.

## 4. Reports and comparison
fg-report/2 extends schema3 snapshots. Word includes a detector schedule; Excel includes detector/mount/readiness/performance schedules; each format includes readable overview and full audit rows. Long audit values are chunked without data loss. Normalized JSON retains raw source assets and full calculation_artifacts, plus full before/after comparison values; large comparison cells refer to those full values by path/hash. PDF embeds fonts shipped with pinned reportlab. Parser QA checks field names, IDs and values; actual Qt PNG hash/camera retained. Revision compare requires the same case UUID and stable object IDs. Changes in exclusions/performance links/basis/draft-subject hash are exposed; comparison is not acceptance or automatic merge. Native Office, large production studies and full professional template/history requirements remain open.

## 5. Recovery and Windows preparation
Backups are opened read-only and checked for schema1/2/3, SQLite integrity and FK consistency under a256MB bound. Restore installs a NEW .fgcase through a private temporary file and exclusive hard-link creation, appends named restoration audit and preserves the original UUID/history. It never overwrites an existing case or original backup. Cancellation reaps the job and removes only its random-token temporary files; if installation raced cancellation, inspect the new destination before retrying. The Win32 process probe has ALIVE/DEAD/UNKNOWN states; query/access failure remains UNKNOWN and cannot authorise stale-lock cleanup. Mocks test branches, not real Windows DLL/OS behaviour. Stable native writer fencing remains required before cleanup. No external process is killed. Real NTFS/Win32/cloud-sync and crash acceptance remain pending.

## 6. Performance preparation
fg-performance-preparation/1 is a closed SYNTHETIC-only contract, bounded raw text and1..2000 exact sample rows with mandatory source/revision/licence/conditions/units. Raw bytes/text SHA is retained. Dataset identity is immutable-by-new-ID; linking requires exact manufacturer/model/sensitivity and evidence. Exact-source lookup only returns an already supplied row for exactly matching conditions. It refuses interpolation/extrapolation and returns NOT DETECTOR RESPONSE. The sample fixture is generated software data, explicitly not vendor data. No real manufacturer catalogue is supplied or authorised. The draft-review ledger allows DRAFT_REVIEW/NEEDS_INFORMATION/REJECTED only, captures reviewer/rationale/evidence/current subject hash, and has no approval/promotion path. Modified subjects make reviews stale. Generic workspace commands refuse promotion of preparation records; externally tampered statuses are surfaced as blockers.

## Compatibility and programme
Schema3 migration is explicit/backup-protected and candidate only. Original migrations1/2 and owner manifest unchanged. Schema1/2 cases continue opening; no automatic schema promotion. Reports identify actual stored review states rather than masking them. FK corruption is refused on open and backup verification. No full WP02–WP12 acceptance is claimed. WP05/06 engineering response, WP08 risk validity, WP09 engineering optimisation, live WP10/11 and WP12 qualification remain gated by data, method references, permissions and independent review.
