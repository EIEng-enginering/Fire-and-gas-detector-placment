## Defects found on Windows and fixes
1. **fsync on read-only descriptors (97 errors).** `create_case`, `CaseSession.save`, `_backup` and `restore_as_new` flushed files with `open(path,'rb')` + `os.fsync`. Windows `_commit` requires a write-capable handle and raises `OSError [Errno 9] Bad file descriptor`. Fix: new `services/case.py:fsync_file()` opens `'r+b'` (update, no truncation) and is used at all four sites (`case.py` ×3, `recovery.py` ×1). POSIX behaviour is unchanged.
2. **SQLite connections not closed (WinError 32).** `with sqlite3.connect(...) as con:` commits/rolls back but does not close the connection, so Windows keeps the file locked until garbage collection; temporary-directory cleanup, rename and delete then fail. Source fixes with `contextlib.closing`: `recovery.inspect_backup` (read-only verification of every backup/restore), `geometry.enable_geometry` and `study_schema.enable_study` pre-upgrade backups, `preparation_job.PreparationJob` snapshot. The same pattern in three inherited test files (`test_backup_restore.py`, `test_case_lifecycle.py`, `test_geometry_store.py`, 8 sites) and in `tools/build_return_pack.py` was changed to `with closing(sqlite3.connect(X)) as c, c:` — identical commit semantics plus close. No assertion, tolerance, expected value or test selection changed.
3. **Remaining Windows failure — not fixed, not weakened:** `test_case_hardening.test_symlink_alias_fenced` requires symlink creation. This PC has no Developer Mode and no `SeCreateSymbolicLinkPrivilege` (WinError 1314). This is the documented checklist prerequisite; the test is retained unchanged and fails on this host.
